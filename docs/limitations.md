# 支援範圍與限制

## 轉換行為

- 由來源核心解碼 Anvil 儲存，包括額外 ID/data 與多層儲存，避免將海草、水等第二層資料遺失。
- 依來源 canonical palette 的 NBT 屬性型別建立持久化狀態，使用目標核心的版本遷移；無法解析的狀態停止轉換，不替換成空氣。
- 每層寫入後以嚴格 palette 解碼逐位置比對，區域寫入後重新開啟 LevelDB 逐記錄讀回。
- 舊 BiomeColors 透過來源核心的 BiomePalette 解碼；現代 Biomes、HeightMap、block light、方塊實體、一般實體與 pending ticks 另行處理。
- 一般實體依 floor(Pos)/16 歸位，保留每筆原始 NBT 位元組。目標區塊不存在時停止。

## 未保證的行為

- 僅處理主世界 dimension 0。其他維度不可直接放入此流程。
- MovingBlock、活塞動畫、嵌入的舊方塊/物品格式及所有實體種類沒有全面行為驗證。原始 NBT 保留不等於遊戲行為完全相容。
- 空白實體 id 無法建立；保留記錄並警告。核心將來儲存已載入的區塊時可能不再寫回此類無效記錄，因此保留離線輸出與備份。
- 光照與 pending ticks 的完整遊戲行為尚未全面驗證；不能把載入成功等同排程語意完全一致。
- 目前輸出 generatorName=void，避免驗證期間生成新地形；需要新地形的伺服器必須另外決定產生器及參數。
- 來源原有 metadata 不保證都能被目標核心解讀。插件、玩家資料、權限、傳送點及外部 SQL 資料不屬於地圖轉換。
- 新版核心可能改變 API、palette 或 NBT 格式；更新前先用小世界重新驗證。

## 安全與續跑

來源保持不變；只有 after、reports、intermediate 和 backups 會寫入。以獨立副本測試，禁止目標伺服器與轉換器同時使用同一資料庫。實體歸位會改變區塊內的記錄分布，不能再直接以來源每區塊實體數判定輸出載入數量。
